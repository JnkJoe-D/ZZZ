# Karpathy Guidelines

将这套规范与仓库根目录 `AGENT.md` 一起使用；若有冲突，以 `AGENT.md`、系统约束和用户当前要求为准。

## 1. 先想清楚再写

- 明确写出关键假设；如果拿不准，不要静默脑补。
- 有多种合理解释时，先指出分歧，再选择最稳妥的实现路径。
- 如果发现更简单或风险更低的方案，主动说明，不要机械执行复杂方案。
- 一旦上下文不够清楚，先停下并命名不确定点，再继续。

## 2. 简单优先

- 只实现用户明确要求的范围。
- 不为单次使用代码引入抽象层。
- 不预埋未被要求的配置项、扩展点或“未来可能会用到”的结构。
- 不为几乎不可能发生的情况堆砌错误处理或防御式代码。
- 写完后自查：能明显缩短、删层级、减状态，就继续简化。

## 3. 手术式修改

- 只改与任务直接相关的代码、资源或配置。
- 不顺手重排格式、不重写相邻注释、不做无关重构。
- 优先匹配现有风格，而不是引入个人偏好。
- 只清理因为本次修改直接产生的无用引用、变量或分支；已有历史遗留问题只提示，不擅自清理。

## 4. 目标驱动执行

- 把“做什么”转换成“如何证明已经完成”。
- 修 Bug 时，先构造复现方式或最小验证，再修复并回归验证。
- 重构时，先明确行为不变的校验方式，再开始动代码。
- 多步骤任务默认先写 2-4 步短计划，每步都带 `verify: ...`。

## 项目内落地

- 与 `AGENT.md` 的目录边界、中文注释、Allman 风格、最小验证流程一起执行。
- 修改 Unity 资源、配置、场景前，先确认是否真的需要落盘；能只改 `Assets/GameClient/**/*.cs` 就不要扩大范围。
- 遇到已有脏工作区时，不回滚与当前任务无关的改动。
- 非 trivial 任务结束前，至少完成一个可追踪验证：编译检查、`tests-run`、`console-get-logs`、目标差异审查等。
